## Vue d'ensemble

HillsRun est une application full-stack de suivi d'entraînement trail running connectée à Garmin. Le projet est **bien structuré** avec des fondamentaux solides : architecture multi-utilisateurs, tokens chiffrés, proxy API sécurisé, PWA offline. L'audit a identifié **56 points d'amélioration** répartis comme suit :

## Architecture

### Points forts

- **Séparation claire** : Backend FastAPI (async) + Frontend Next.js App Router
- **Multi-utilisateur** : Toutes les tables Garmin ont un `user_id` FK, sync per-user
- **Proxy API sécurisé** : Next.js `/api/garmin/[...path]` injecte `X-API-Key` côté serveur (jamais exposé au client)
- **Tokens chiffrés** : OAuth Garmin stockés en Fernet (AES) dans la DB
- **TanStack Query** bien configuré : `staleTime`, invalidation, pas de polling inutile
- **PWA** : Service worker Serwist avec support offline
- **Coach mode** : React Context + headers pour la vue multi-tenant

### Points faibles

- **`database.py` monolithique** (1635 lignes) : toutes les requêtes pour ~15 tables mélangées
  - **Recommandation** : découper en modules par domaine (`activities_queries.py`, `user_queries.py`, etc.)
- **Migrations SQL manuelles** (fichiers `sql/01_schema.sql` à `10_day_preferences.sql`)
  - Pas d'outil de migration (Alembic, etc.) — risque de drift entre environnements
- **Queue de sync en mémoire** (OrderedDict, 50 jobs max) : perdue au redémarrage
  - Acceptable pour le moment, mais envisager Redis si scaling

## Sécurité (OWASP Top 10)

### 1. Injection — ✅ SÉCURISÉ

Toutes les requêtes utilisent des paramètres préparés asyncpg (`$1`, `$2`). Aucune concaténation SQL détectée.

### 2. Authentification — ⚠️ PROBLÈMES

| # | Problème | Sévérité | Fichier |
|---|----------|----------|---------|
| S1 | **Pas de rate limiting sur `/auth/connect` et `/connect/mfa`** | 🔴 CRITIQUE | `src/api/routers/auth_garmin.py:133,186` |
| S2 | ~~**Sessions MFA en mémoire** sans TTL garanti~~ — ✅ Corrigé le 13/03 (background cleanup task avec TTL 5min) | ✅ | `src/api/routers/auth_garmin.py` |
| S3 | Pas de rate limiting sur les endpoints d'authentification | 🔴 CRITIQUE | `src/api/routers/auth_garmin.py` |
| S4 | Vérifier config Better-Auth (secure cookies, CSRF, sameSite) | 🟡 MOYENNE | `web/src/lib/auth.ts` |

**Recommandation S1/S3** : Implémenter `slowapi` ou middleware custom :
```python
from slowapi import Limiter
limiter = Limiter(key_func=get_remote_address)

@router.post("/connect")
@limiter.limit("5/15minutes")
async def connect_garmin(...):
```

### 3. Exposition de données sensibles — ⚠️ PROBLÈMES

| # | Problème | Sévérité | Fichier |
|---|----------|----------|---------|
| S5 | **Messages d'erreur détaillés exposés** : `f"Failed to link Garmin account: {e}"` | 🟡 MOYENNE | `auth_garmin.py:116-119` |
| S6 | **PII dans les logs** : email utilisateur logué en clair | 🟡 MOYENNE | `auth_garmin.py:171` |

### 4. XSS / XXE — ✅ SÉCURISÉ

Pas de `dangerouslySetInnerHTML`, pas de parsing XML, réponses JSON uniquement.

### 5. Contrôle d'accès — ✅ BON

- Ownership vérifié sur toutes les requêtes (`WHERE user_id=$2`)
- Coach access validé via `verify_coach_access()`
- Header `X-Garmin-User-Id` injecté par le proxy (pas manipulable côté client)

### 6. Mauvaise configuration — ⚠️ PROBLÈMES

| # | Problème | Sévérité | Fichier |
|---|----------|----------|---------|
| S8 | **Headers de sécurité manquants** : X-Content-Type-Options, X-Frame-Options, HSTS, Referrer-Policy | 🟠 HAUTE | `web/next.config.ts` |
| S9 | ~~**CORS non configuré** sur FastAPI~~ — ✅ Corrigé le 13/03 (origins restreints à app.hillsrun.com + localhost:3000) | ✅ | `src/api/main.py` |
| S10 | **CSP** uniquement sur `/sw.js`, pas sur l'application | 🟡 MOYENNE | `web/next.config.ts` |
| S11 | Debug logging activé pendant sync | 🔵 BASSE | `src/api/routers/sync.py:89` |

**Recommandation S8** : Ajouter les headers dans `next.config.ts` :
```typescript
async headers() {
  return [{
    source: "/(.*)",
    headers: [
      { key: "X-Content-Type-Options", value: "nosniff" },
      { key: "X-Frame-Options", value: "DENY" },
      { key: "Strict-Transport-Security", value: "max-age=31536000; includeSubDomains" },
      { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
    ],
  }];
}
```

**~~Recommandation S9~~** : ✅ Corrigé le 13/03 — CORS configuré avec `allow_origins` restreint à `app.hillsrun.com` + `localhost:3000`, méthodes et headers explicites.
